Kafka Broker 는 Partition에 대한 Read 및 Write를 관리하는 소프트웨어로
Kafka Server라고 부르기도 한다.

## Broker의 특성
- Topic 내의 Partition들을 분산, 유지 및 관리

- 각각의 Broker들은 ID로 식별됨( ***고유한 숫자값*** )
	-> Broker ID와 PartitionID와는 아무런 관계 없다.

- Topic의 일부 Partition들을 포함
	-> Topic 데이터의 일부분을 분산하여 Partition단위로 Broker가 나눠가짐
	
- Kafka Cluster: 여러 개의 Broker들로 구성됨

- 최소 3대 이상 Broker로 Cluster로 구성해야함
	- 4대 이상 권장(ZooKeeper mode 사용 시)
	- Upgrade 등 작업 시 Broker를 순차적으로 Shutdown 시, 정상동작을 위함
	- ZooKeeper mode 가 아닌 KRaft mode 에서는 3대 이상 권장

Topic 생성 시 Kafka가 자동으로 Topic을 구성하는 Partition들을 Broker들에게 할당해줌


## Bootstrap Servers
모든 Kafka Broker는 Bootstrap 서버라고 부른다.
Client는 특정 Broker에 연결하면 전체 클러스터에 연결된다.
하지만 특정 Broker 장애를 대비하여 전체 Broker LIst를 파라미터로 입ㄹ
