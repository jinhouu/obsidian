## Partitioner
![[Pasted image 20251230174040.png]]

Partitioner는 해당 토픽의 파티션 갯수를 알고있다.
Key값을 지정한 경우 특정 알고리즘에 의해 파티션을 지정하여 전달

![[Pasted image 20251230174233.png]]
Partitioner는 개발하여 교체 가능하다.

- Message == Record == Event == Data
- Message 는 Header와 Key 그리고 Value로 구성
- Kafka는 Record(데이터)를 Byte Array로 저장
- Producer는 Serializer, Consumer는 Desirializer를 사용
- Producer는 Message의 Key 존재 여부에 따라 Partitioner를 통한 메시지 처리 방식이 다르다.

# Producer Acks
acks 는 Producer가 메시지 발행 요청이 성공할 때를 정의하는데 사용되는 파라미터이다.

## acks=0
Kafka Partition에 써졌는지 응답을 받지 않고, 발행 후 결과에 상관없이 성공으로 간주.
손실이 발생할 수 있지만, 가장 빠르게 메세지를 보낼 수 있다.
## acks=1 (defalut)
Leader에게 메세지가 전달 되면 Kafka가 성공 응답을 보낸다.
Follower들에게는 복제 되었는지 확인하지 않으며,
Follower에게 복제 전 장애 시 유실 가증성.

`At Most Once(최대 한번)`를 보장한다
## acks=all (acks=-1 과 동일)
모든 ISR들에게 복제 되었을 때 성공 메세지를 받는다.
레코드 유실이 가장 낮지만
