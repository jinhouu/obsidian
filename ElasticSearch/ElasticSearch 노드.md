## 마스터 노드
- ElasticSearch 클러스터의 핵심 관리자, 클러스터의 안정적인 운영을 책임짐
- 클러스터 내 인덱스 생성 및 삭제, 노드관리, 샤드 분배 등의 결정의 역할
- 클러스터의 연속적인 서비스 제공(고가용성)을 위해 적어도 한개 이상의 마스터 노드 필요
- 운영환경에서는 3개 이상의 마스터 노드를 두어 장애 발생 시 안정성을 보장하는 것을 권장
- 클러스터 상태를 모니터링 하며, 필요한 경우 마스터 노드 역할을 수행할 수 있는 노드로의 전환을 관리
## 데이터 노드
- ElasticSearch 클러스터에서 데이터를 실제로 저장하고 관리하는 역할
- 색인, 검색, 집계 등을 담당하며, CPU, I/O, 메모리와 같은 하드웨어 리소스를 많이 소모
- 클러스터 안정성을 위해, 적절한 수의 노드를 유지하고 장애 발생시를 대비해 적절한 샤드 운영을 해야함
- 데이터 노드의 종류에는 여러가지가 있으며, 데이터의 특성과 접근 패턴에 맞게 조정
	- data_content: 지속적으로 유지되어야 하는 데이터 저장(주로 읽기 작업이 많은 검색 및 집계 쿼리)
	- data_hot: 최신 시계열 데이터를 빠르게 읽고 쓰는데 필요(고성능 SSD 같은 저장장치를 사용하여 최근 데이터 Index)
	- data_warm: 쿼리 빈도가 낮은 데이터 보관(비용 효율적인 HDD 사용)
	- data_cold: 빠르게 검색할 필요가 없는 오래된 데이터를 보관
	- data_frozen: 거의 사용되지 않거나 아카이브 목적의 데이터를 저장 (데이터 보존이 주 목적)
- 데이터 노드의 구성은 성능 최적화와 클러스터의 안정성, 비용적인 측면에서 직접적인 영향을 끼침
## 인제스트 노드
- 데이터 수집, 가공 및 색인 전달 과정을 관리하는 노드
- 데이터를 전처리하여 다양한 소스의 데이터를 효과적으로 처리하고, 필터링, 파싱 변환 등 데이터를 최적화
- 로그, 센서데이터, 웹 크롤링 결과 등 다양한 데이터 유형을 처리할 수 있으며, 이를 가공하여 데이터 노드에 색인하여 저장
- 데이터 처리 과정에서 리소스 사용이 높기 때문에 인제스트 노드와 데이터 노드를 분리하여 운영하는 것이 좋음
- 인제스트 노드는 데이터 노드와 함께 구성되어 데이터 처리 및 색인 프로세스를 효율적으로 수행

## 그 외 노드들..
### 코디네이팅 노드 
- 클러스터의 요청을 라우팅하고 상태를 관리하느 ㄴ역할
- 대규모 클러스터에서는 별도로 분리하여 운영
### 머신러닝 노드
 - 머신러닝 기능을 제공
 - 데이터학습, 이상탐지, 예층 등 작업을 처리
### 리모트 클러스터 클라이언트
 - 다른 클러스터와 연결을 관리
 - 여러 클러스터 간 데이터 검색이 가능하게 담당
### Transform 노드
- 인덱스 간 데이터를 자동으로 복사하거나 변환
